# إضافة رغوة للواتساب (تذكير باستلام الطلب)

إضافة كروم (Manifest V3) تفتح قائمة "تذكيرات اليوم" من رغوة داخل واتساب ويب، محادثة محادثة، والنص مكتوب كمسودة. **الإضافة ما ترسل أي رسالة بنفسها.** الموظف يراجع ويضغط Enter، وبعد الإرسال تنفتح المحادثة اللي بعدها تلقائياً.

## الملفات
| الملف | وين يشتغل | وش يسوي |
|---|---|---|
| `manifest.json` | — | الصلاحيات: `storage` فقط، والمواقع: web.whatsapp.com و localhost و ragwapos.com (و www و staging) |
| `background.js` | خلفية الإضافة | يحفظ القائمة والتأكيدات بـ`chrome.storage.local`، ويفتح/يختار تبويب واتساب ويب |
| `bridge.js` | صفحات رغوة | يوصل بين صفحة رغوة (`window.postMessage`) وخلفية الإضافة |
| `whatsapp.js` | واتساب ويب | يفتح كل محادثة بنفس التبويب، يكتب المسودة، يلاحظ إرسال الموظف، ويعرض اللوحة (عدّاد، تخطي، إيقاف) |
| `icons/` | — | أيقونات 16 و48 و128 من شعار رغوة |
| `STORE_LISTING.md` و`store/` | — | نصوص وصور Chrome Web Store (ما تدخل بالحزمة) |

## نسخة المتجر
- `manifest.json` هنا نسخة التطوير: تشتغل كمان على `localhost` و`staging.ragwapos.com` للتجربة.
- `npm run build:extension` يبني `dist-extension/ragwa-whatsapp-extension-<version>.zip` للمتجر بصلاحيات الإنتاج بس (`web.whatsapp.com` و`ragwapos.com` و`www.ragwapos.com`)، ويرفض البناء لو صارت الصلاحيات أوسع من كذا.
- خطوات النشر ونصوص كل خانة بلوحة المطوّر: `STORE_LISTING.md`.

## الأمان
- ما فيها أي مفتاح أو رابط لقاعدة البيانات، وما تسوي أي طلب شبكة. كل الكتابة بالقاعدة تصير من صفحة رغوة المسجّل فيها الدخول، وتمر بصلاحيات RLS العادية.
- كل تذكير يحمل معه سجله، ورغوة ما تكتب إلا السجلات اللي تخص نفس المحل المسجّل دخوله. قاعدة البيانات نفسها ترفض أي سجل لفاتورة مو تابعة للمحل.
- الإضافة ما تضغط Enter ولا زر الإرسال أبداً. "أُرسل" ينحسب فقط إذا الموظف ضغط Enter (أو زر الإرسال) بنفسه، وبعدها فضي صندوق الرسالة.

## ملاحظة على واتساب ويب
شكل صفحة واتساب ويب مو واجهة رسمية ويتغير بدون إشعار. كل اللي يعتمد عليه موجود بمكان واحد: قسم `SELECTORS` بأول `whatsapp.js` والدوال الثلاث اللي تحته. إذا وقفت الإضافة عن فتح المحادثات أو عن ملاحظة الإرسال بعد تحديث من واتساب، هذا المكان اللي يتعدّل.
